Immediately after intake, status reports an `XS`–`XL` workload, estimated token range, confidence, and reasons. These are estimates, not fixed promises. At the 80% boundary SpecToPR checkpoints and continues from compact context; at the hard limit it splits scope or waits for a user decision without removing anything from `requiredValidations`.

## Use this case <span id="use-this-case-figma"></span>

Use this case when Figma is the primary source and real APIs are out of scope. Implement deterministic mock-backed UI, compare the result with connected-host Figma PNGs, and publish a **draft PR by default**.

:::tip[Input / result]
**Input:** repository + valid Figma URL · **Result:** mock-backed UI, measured Figma ratio/diff/overlay, independent review, and a 15-section draft PR
:::

## Required inputs <span id="required-inputs-figma"></span>

| Input         | Requirement                                                  |
| ------------- | ------------------------------------------------------------ |
| Repository    | Target Git repository with its design system and screen code |
| `mode`        | `figma`                                                      |
| `scope`       | `ui` is required                                             |
| `figmaUrl`    | Accessible file URL, preferably with a concrete `node-id`    |
| `publication` | Defaults to `draft`; use `none` to stop after reviews        |
| Request       | Name screens, states, and responsive boundaries to implement |

## Optional inputs <span id="optional-inputs-figma"></span>

- `briefPath` and `docsPaths` add copy and state descriptions.
- `guidancePaths` supplies design-system, architecture, and folder-structure rules.
- `skillHints` requests applicable installed design-system, React/Next, and accessibility skills.

```text
/spec-to-pr /absolute/path/to/app
mode: figma
scope: ui
figmaUrl: https://www.figma.com/design/FILE/checkout?node-id=12-345

Implement the Figma design with deterministic mock data, compare it at the 98% threshold, and publish a draft PR.
```

```text
changeKind: design
publication: draft
Implement desktop/mobile and loading/error/success states for node 12:345 with existing components.
Create real Figma `visualTargets`, deterministic mock states, exact/review ratios, diff, overlay, independent review, and a draft PR.
```

## What SpecToPR does <span id="process-figma"></span>

1. **Intake:** Confirm URL, node, screen/state scope, publication intent, and workload estimate.
2. **Figma contracts:** Through the connected host, read node IDs, variables, component context, screenshots, and assets into a project-local strict manifest.
3. **Design-system mapping:** Match the design to existing components and tokens before creating custom markup.
4. **Implementation:** Submit a strict mock JSON manifest shaped as `{deterministic:true, fixtures:[{path, sha256}]}` plus separate fixtures. Each `sha256:` digest binds the fixture contents before responsive layout and loading/error/empty/success states are implemented.
5. **Compare / reviews:** Every actual capture repeats the target route/state/viewport/device scale/fixture and records provider, ISO capture time, PNG path, and `sha256:` digest. Runtime rejects target drift or digest mismatch before `compare-visuals` computes exact/review ratios, masks, diff, and overlay at a minimum 98%, with at most 20% justified masking and three total comparison attempts (the initial comparison plus at most two repairs); reviewers independently judge interaction and accessibility.
6. **Report / publish:** Create packet-bound 15-section `pr-report-v2.1` and publish the draft.

Every report section is `complete`, `not-run`, `blocked`, or `not-applicable`; stale paths outside the current review packet are omitted. GitHub images, diffs, and overlays use immutable paths on one managed `spec-to-pr/evidence` branch and URLs pinned to the upload commit SHA, not a branch per Run.

## Execution policy: stages, agents, skills, and tools

| Durable stage       | Exact behavior for this case                                                                               |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| `intake`            | Fix the Figma file/node, UI states, responsive scope, publication, and workload.                           |
| `contracts`         | Read real node/variables/assets/screenshots from the connected host and submit a strict `figma-bundle`.    |
| `implementation`    | One implementation writer maps the design system and implements deterministic mock-backed UI.              |
| `functional-review` | The read-only `functional-reviewer` judges state behavior and relevant project checks.                     |
| `design-review`     | The read-only `design-reviewer` judges visual/interaction/responsive/accessibility evidence against Figma. |
| `report`            | Build 15-section `pr-report-v2.1` provenance, visual ratio/assets, review, gap, and blocker reporting.     |
| `publish`           | Create the packet-bound draft and synchronize current visual assets when ready.                            |
| `archive`           | Run only after a published draft merges, authoritative evidence exists, and the user requests it.          |

Agent policy allows zero read-only scout workers for XS/S, at most one for M, and at most two for L/XL. Scouts only perform independent read-heavy Figma/repository mapping. One implementation writer edits: **no nesting**, no **parallel writer**. Reviewers may run in parallel only for L/XL after implementation.

- `stageSkillRoute`: public actions route `intake-contracts` → `implement` → `review-functional`/`review-design`, adding `publish` for draft delivery. This routing is not `deliveryProfile.recommendedSkills`.
- `recommendedSkills`: `figmaUrl` → `figma`, `design-system`; `openApiPaths` → `api-generator`; detected React/Next packages → `react-best-practices`, `next-best-practices` optional candidates.
- Figma UI alone does not recommend `playwright`; only the `mode: feature` + UI mapping adds that candidate.
- `appliedSkills`: record only the allowed union of `recommendedSkills` and available/applicable optional `skillHints`. Missing optional skills do not block, but real Figma evidence is not optional.
- **workflow MCP:** required. **Figma host:** required to read the URL's file/node and cannot be replaced by runtime polling. **Playwright Test/CLI:** use focused runtime assertions when `requiredValidations` require them; this profile does not inherit feature E2E or video.
- **Browser MCP:** optional interactive visual inspection. **Chrome DevTools MCP:** conditional for console/network/performance/memory/live-DOM diagnosis. Screenshots or DevTools observations never replace assertions.

### Ready, blocked diagnostic, and resume

The normal result is a draft from `workflow_publish intent: ready`. Ready and blocked use the same 15-section `pr-report-v2.1`; a blocked draft exposes the stopped stage, unrun validations, and exact unblock action. Only passing preflight may create `workflow_publish intent: blocked-diagnostic`, which stays `status: blocked`. `PUBLISH_NO_DELTA` returns a **local blocked report** without empty commits or issue fallback.

If an explicitly requested draft returns `diagnostic-publication-uncertain`, never publish automatically. Inspect GitHub/GitLab for a matching draft, show the result to the user, and call the same `workflow_publish` action with `recoverUncertain: true` only after explicit approval.

After fixing access, node, or evidence, resume the **same Run** at its latest status. If a diagnostic draft exists, update the same source/target **same draft PR** from `[Blocked]` to the normal `intent: ready` title/body and remove the blocked label.

## Evidence and validation <span id="evidence-figma"></span>

| Evidence               | Illustrative path                                                    | Passing condition                                                                           |
| ---------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Bundle                 | `evidence/figma/figma-bundle.json`                                   | `provider: host-connected-figma`, ISO `capturedAt`, matching `fileUrl`, non-empty `nodeIds` |
| Manifest/visuals       | `evidence/figma/manifest.json`, `evidence/figma/checkout-mobile.png` | Project-local strict manifest and actual PNG `visualPaths`                                  |
| Visual comparison      | `evidence/visual/figma-report.json`                                  | exact/review ratio ≥ 98%, baseline/target/diff/overlay                                      |
| Mock fixtures          | `evidence/fixtures/checkout.json`                                    | deterministic loading/error/empty/success data                                              |
| Responsive/interaction | `evidence/design/responsive.json`, `interaction.json`                | Named viewports and state transitions are verified                                          |
| Accessibility          | `evidence/design/accessibility.json`                                 | Semantic, keyboard, focus, and contrast checks pass                                         |
| Design review          | `evidence/reviews/design.json`                                       | Independent approved verdict over frozen diff/evidence                                      |

Figma mode does not automatically require feature-targeted E2E and video. If complete feature delivery and video are the goal, choose `mode: feature` and compose `figmaUrl` as a source.

## Expected draft PR <span id="expected-pr-figma"></span>

**Illustrative expectation title:** `feat: implement checkout from Figma`

```md
## Figma source

- file/node: checkout / 12:345
- bundle: evidence/figma/figma-bundle.json

## Implementation

- existing design-system components and tokens
- desktop/mobile and loading/error/success states

## Design validation

- exact match: 97.84%; review match: 99.12%; threshold: 98%
- baseline / target / diff / overlay links
- responsive / interaction / accessibility: passed
- design-reviewer: approved

## Known differences

- states not defined in Figma and intentionally excluded scope
```

## When the Run stops <span id="blockers-figma"></span>

| Blocker                                         | User action to resume                                               |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| Invalid or inaccessible URL/node                | Supply an accessible URL and exact node ID                          |
| Connected-host evidence cannot be read          | Restore Figma connection, login, or permission                      |
| Required state or viewport is absent            | Supply authoritative behavior or approved supplemental requirements |
| Existing design system conflicts with Figma     | Decide whether to reuse, extend, or allow an exception              |
| Draft requested from a dirty/uncommitted branch | Commit only intended files and satisfy clean preflight              |

## What this case does not do <span id="exclusions-figma"></span>

- It does not claim nodes, variables, or components from the URL alone.
- It does not poll Figma or add a dedicated runtime microtool.
- It does not add real API clients, API gaps, Web Vitals, feature E2E, or video by default.
- It does not implicitly add the feature mode's full user-feature E2E and video contract.
