# Install SpecToPR

The product name is **SpecToPR**. The repository, installation ID, and command identifier are `spec-to-pr`.

<Tabs groupId="host">
<TabItem value="claude" label="Claude Code" default>

## Marketplace installation

In a Claude Code session:

```text
/plugin marketplace add dhyun2/spec-to-pr
/plugin install spec-to-pr@spec-to-pr
```

Run `/reload-plugins` or start a new session after installation.

Update:

```text
/plugin marketplace update spec-to-pr
/plugin update spec-to-pr@spec-to-pr
/reload-plugins
```

## Run from local source

```bash
git clone https://github.com/dhyun2/spec-to-pr.git
cd spec-to-pr
corepack enable
pnpm install
pnpm build
claude --plugin-dir /absolute/path/to/spec-to-pr
```

## Local marketplace installation

```bash
git clone https://github.com/dhyun2/spec-to-pr.git
cd spec-to-pr
corepack enable
pnpm install
pnpm build
codex plugin marketplace add .
codex plugin add spec-to-pr@spec-to-pr
```

Reopen Codex and start a new task. Use `/plugins` to verify the SpecToPR marketplace and `spec-to-pr` installation.

## Verify installation

```text
/spec-to-pr:doctor
```

Doctor calls `workflow_info` and verifies contract version `2.0.0` plus:

- 7 tools
- 8 durable stages
- 2 reviewer roles
- explicit API-ready-before-UI, independent reviews, and conditional design review capabilities

A release package may omit `node_modules`. Diagnose the host-exposed `workflow_info` instead of importing an SDK directly from plugin cache.

## Installed components

- 8 public marketplace skills
- local stdio MCP server launched by `node ./dist/mcp/server.js`
- `functional-reviewer` and `design-reviewer` definitions
- evidence ledger, artifact storage, draft publisher, and explicit archive runtime

Hosts may display a different tool namespace, but the public contract is identical.
