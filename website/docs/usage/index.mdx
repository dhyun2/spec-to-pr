## 30초 선택 기준

| 출발점              | 필수로 주는 것                             | 비교 기준                          | 초안 PR에 더해지는 것                       |
| ------------------- | ------------------------------------------ | ---------------------------------- | ------------------------------------------- |
| 제품/화면 전체 개발 | 기획서 + Figma + OpenAPI                   | Figma ↔ 결과 화면                  | API 사용·누락, 화면 일치율, Web Vitals      |
| 레거시 마이그레이션 | 대상 저장소 + 실행 가능한 별도 레거시 경로 | 실행한 레거시 ↔ 결과 화면          | 이관 목록·완료 현황, 이관·제외 근거         |
| 한 기능 개발        | 기획서 + Figma + OpenAPI                   | Figma ↔ 결과 화면                  | 해당 기능 E2E + 재생 가능한 영상 정확히 1개 |
| 디자인 구현         | Figma URL + 대상 저장소                    | Figma ↔ 모의 데이터 기반 결과 화면 | 수치화된 화면 비교, 실제 API 연동은 제외    |

:::tip[입력 자료를 함께 사용해도 됩니다]
`mode`는 결과물과 필수 검증 자료를 정하고, 입력 자료는 필요한 만큼 조합할 수 있습니다. 예를 들어 `feature` 방식에는 기획서, Figma, OpenAPI, 프로젝트 지침을 함께 줄 수 있습니다.
:::

## 모든 사용법이 공유하는 약속

한 명의 구현 담당자가 코드를 작성합니다. 모든 변경은 `functional-reviewer`가 독립적으로 확인하고, UI 작업은 `design-reviewer`가 한 번 더 확인합니다. 두 검토자는 변경할 수 없는 동일한 검토 묶음을 사용합니다. 화면 비교는 고정 검토 일치율 `92%` 이상, 제외 영역 `20%` 이하를 요구하며 유효 비교 세 번을 자동으로 수행합니다. 취득 오류는 횟수를 쓰지 않고, 세 번째 유효 실패는 자동 보정만 멈춘 뒤 실패 화면을 화면 비교 Gap으로 남깁니다. 집중 UI 검증은 전체 점수와 독립적입니다. [시각 검증](/concepts/visual-verification)에서 계산 방법을 자세히 볼 수 있습니다.
