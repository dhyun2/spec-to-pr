title: 레거시 이관
---

`legacy`는 별도의 레거시 프로젝트에 있는 특정 기능을 대상 프로젝트로 옮길 때 사용합니다.

레거시 이관은 OpenSpec 문서나 `test: on | off` TDD 모드를 만들지 않고, 실행 중인 레거시 동작·화면·API를 직접 구현 기준으로 사용합니다.

## 입력

```yaml
case: legacy
projectRoot: /absolute/path/to/new-project
legacyProjectRoot: /absolute/path/to/legacy-project
request: 주문 내역 목록과 상세 이동을 이관해줘
```

## 가장 중요한 규칙

**레거시 프로젝트는 읽기 전용입니다.** 대상 프로젝트에만 코드를 작성합니다.

## 무엇을 기준으로 옮기나요?

- 사용자가 요청한 기능의 화면과 상태
- 실제 사용자 동작
- 그 기능이 호출하는 실제 API
- 대상 프로젝트의 기존 구조와 컴포넌트 규칙

디자인 시스템을 사용할 수 있다면 결과가 레거시 동작과 화면을 유지하는 범위에서 사용합니다.

## 화면과 API 확인

실행 중인 레거시 화면을 기준으로 캡처하고, 대상 프로젝트의 같은 화면과 비교합니다. 레거시에서 확인한 실제 HTTP 호출 중 대상 프로젝트에서 사용한 것만 PR의 API 표에 기록합니다.

정확한 메서드·경로를 확인할 수 없으면 추측하지 말고 Gap으로 기록합니다.

## PR 예시

```md
# [레거시 이관] 주문 내역 목록과 상세 이동

> Draft PR · 화면 93.10% · Gap 1개

## 개발한 기능

- 주문 내역 목록을 조회하고 항목을 누르면 주문 상세로 이동할 수 있습니다.

## 화면 일치율

| 화면 | 비교 기준 | 비교 횟수 | 일치율 | 결과 | 증빙 |
| 주문 내역 목록 | 실행 중인 레거시 화면 | 1/3 | 93.10% | 통과 | 기준 · 구현 · Diff |

## 사용한 API

| Method | Path | 사용 목적 |
| GET | /orders | 주문 내역 목록 조회 |

## Gap

| 확인 또는 개발이 필요한 내용 | 영향 | 다음 작업 |
| 주문 취소 버튼의 권한 정책 | 중간 | 레거시 정책 확인 후 버튼 노출 반영 |

## 검증

- 목록 조회와 상세 이동 회귀 테스트 통과
```
