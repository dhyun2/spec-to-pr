`figma`는 선택한 Figma 화면과 상태를 기준으로 UI를 구현할 때 사용합니다.

Figma는 OpenSpec 문서나 `test: on | off` TDD 모드를 만들지 않고, 선택한 화면·상태를 직접 구현 기준으로 사용합니다.

## 입력

```yaml
case: figma
projectRoot: /absolute/path/to/project
request: 결제 수단 선택 화면을 구현해줘
figmaUrl: https://www.figma.com/design/FILE/checkout?node-id=12-345
```

## 구현 규칙

- URL이 가리키는 화면과 상태를 기준으로 구현합니다.
- 사내 디자인 시스템의 컴포넌트·토큰을 우선 사용합니다.
- 정확히 대응하는 컴포넌트가 없으면 프로젝트 규칙에 맞춰 직접 구현합니다.
- 디자인 시스템과 정확히 일치하지 않는다는 이유만으로 Gap을 만들지 않습니다. 화면이나 기능을 완료하지 못했을 때만 Gap입니다.

## 화면 비교

Figma 캡처를 기준 이미지로, 실행 중인 대상 프로젝트의 같은 화면을 구현 이미지로 사용합니다. 두 이미지는 같은 경로·상태·데이터·화면 크기여야 합니다.

```bash
node /absolute/path/to/compare-images.cjs \
  --baseline spec-to-pr-evidence/payment/baseline.png \
  --actual spec-to-pr-evidence/payment/actual.png \
  --diff spec-to-pr-evidence/payment/diff.png
```

일치율이 92% 미만이면 Diff를 보고 구현을 보완한 뒤 같은 조건으로 다시 비교합니다. 최초 비교를 포함해 최대 3회까지 시도하고, 세 번째도 92% 미만이면 1·2·3차 Diff와 다음 작업을 Gap에 기록합니다.

## PR 예시

```md
# [Figma 화면 구현] 결제 수단 선택

> Draft PR · 화면 94.20% · Gap 1개

## 개발한 기능

- 저장된 카드와 새 카드 입력을 전환할 수 있습니다.

## 화면 일치율

| 화면 | 비교 기준 | 비교 횟수 | 일치율 | 결과 | 증빙 |
| 기본 상태 | Figma | 1/3 | 94.20% | 통과 | 기준 · 구현 · Diff |

## 사용한 API

| Method | Path | 사용 목적 |
| - | 사용한 API 없음 | - |

## Gap

| 확인 또는 개발이 필요한 내용 | 영향 | 다음 작업 |
| 카드 삭제 정책 | 낮음 | 정책 확인 후 버튼 추가 |

## 검증

- 컴포넌트 테스트 통과
```
