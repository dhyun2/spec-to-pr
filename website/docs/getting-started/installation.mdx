# SpecToPR 설치

제품명은 **SpecToPR**, 저장소·설치 ID·명령 식별자는 `spec-to-pr`입니다.

<Tabs groupId="host">
<TabItem value="claude" label="Claude Code" default>

## Marketplace 설치

Claude Code session에서:

```text
/plugin marketplace add dhyun2/spec-to-pr
/plugin install spec-to-pr@spec-to-pr
```

설치 직후에는 `/reload-plugins`를 실행하거나 새 session을 시작합니다.

업데이트:

```text
/plugin marketplace update spec-to-pr
/plugin update spec-to-pr@spec-to-pr
/reload-plugins
```

## 로컬 소스 실행

```bash
git clone https://github.com/dhyun2/spec-to-pr.git
cd spec-to-pr
corepack enable
pnpm install
pnpm build
claude --plugin-dir /absolute/path/to/spec-to-pr
```

```bash
git clone https://github.com/dhyun2/spec-to-pr.git
cd spec-to-pr

codex plugin marketplace add .
```

## SDK runner

```bash
pnpm --dir packages/codex-sdk install
pnpm --dir packages/codex-sdk build
node packages/codex-sdk/dist/cli.js \
  --cwd /path/to/app \
  --mode brief \
  --brief docs/plan.md \
  --publish
```

## 설치 확인

```text
/spec-to-pr:doctor
```

Doctor는 `workflow_info`를 호출해 contract version `2.0.0`과 다음 표면을 확인합니다.

- tool 7개
- durable stage 8개
- reviewer role 2개
- explicit API-ready-before-UI, independent reviews, conditional design review capability

설치된 release package는 `node_modules`를 포함하지 않을 수 있습니다. plugin cache에서 SDK를 임의 import하는 방식 대신 host에 실제 노출된 `workflow_info`로 진단하세요.

## 설치되는 구성

- public marketplace skill 8개
- `node ./dist/mcp/server.js`로 실행되는 local stdio MCP server
- `functional-reviewer`, `design-reviewer` 정의
- evidence ledger, artifact storage, draft publisher, explicit archive runtime

호스트별 tool namespace 표기는 다를 수 있지만 public contract는 같습니다.
