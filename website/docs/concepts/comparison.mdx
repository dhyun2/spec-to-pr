title: Gap을 남기는 원칙
---

Gap은 실패를 감추지 않는 방법입니다. 개발하지 못한 일, 확실하지 않은 정보, 비교하지 못한 화면을 PR에서 바로 볼 수 있게 적습니다.

## Gap으로 남기는 경우

- 정책이나 요구사항이 비어 있어 구현을 확정할 수 없음
- API의 method, path, 인증 방식이 확인되지 않음
- 테스트가 실패했거나 실행할 수 없음
- 기준 화면이 없어 화면 일치율을 계산하지 못함
- 화면 일치율이 92% 미만임

## 좋은 Gap의 형식

| 확인 또는 개발이 필요한 내용 | 영향 | 다음 작업                        |
| ---------------------------- | ---- | -------------------------------- |
| 쿠폰 중복 적용 정책          | 중간 | 서버 정책 확인 후 제한 로직 추가 |
| 빈 목록 화면 기준 없음       | 낮음 | 승인 화면 수령 뒤 캡처 비교      |

`확인 필요`처럼 짧게 끝내지 말고, 무엇이 비었는지와 누가 다음에 무엇을 판단하면 되는지를 적습니다.

## Gap이 아닌 것

디자인 시스템 컴포넌트가 Figma와 완전히 같지 않다는 사실만으로는 Gap이 아닙니다. 결과 화면과 기능이 요구를 만족하면 됩니다. 실제 미완료나 확인 불가만 Gap으로 남깁니다.
