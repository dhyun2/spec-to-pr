title: 진행 방식
---

SpecToPR는 실행 상태 저장 없이 개발을 진행합니다. 모델이 대상 프로젝트에 맞춰 판단하고 구현하지만, 화면 증빙과 Gap을 통과처럼 바꾸지는 않습니다.

## 네 단계

| 단계      | 모델이 하는 일                                                             | 남기는 것                      |
| --------- | -------------------------------------------------------------------------- | ------------------------------ |
| 자료 확인 | 케이스 자료와 정확한 쓰기 범위를 읽음                                      | 구현 범위와 기준               |
| 구현      | 일반 UI는 디자인 시스템, legacy는 기존 DOM/CSS/assets 보존                 | 실제 Git 변경                  |
| 화면 증빙 | UI 상태를 기준·이관 결과로 캡처·비교                                       | 상태별 일치율·Diff·이미지 링크 |
| 검증      | `test: on` TDD, targeted E2E·영상, 기능·디자인 검토를 가능한 범위에서 실행 | 결과 또는 명시적 Gap           |
| Draft PR  | case 전용 형식으로 현재 변경을 요약                                        | 이관 범위·화면·Gap·검증        |

## 중단 후 다시 시작하기

플러그인이 작업 상태를 저장하지 않습니다. 대신 코드 변경과 화면 증빙은 Git 작업 트리에 남습니다. 중단되면 같은 요청을 다시 실행해 현재 `git diff`에서 이어갑니다.

## 바로 멈추는 경우

아래 상황만 안전을 위해 즉시 멈춥니다.

- 대상 저장소 또는 쓰기 경로를 안전하게 확인할 수 없음
- 레거시 프로젝트를 수정하려는 상황
- 새 브랜치나 커밋을 만들 수 없음

`test: on`의 TDD 미확보, API·binding·인증 분석 실패, 화면 불일치는 멈춤 사유가 아닙니다. 구현 가능한 범위는 계속 진행하고 Gap에 남깁니다. 단, `skipped`나 `waived`는 통과가 아니며 화면 미달이 있는 Draft는 `NOT VERIFIED`입니다.
