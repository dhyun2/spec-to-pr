title: 진행 방식

SpecToPR Lite는 개발을 단계별 시스템으로 통제하지 않습니다. 모델이 대상 프로젝트에 맞춰 판단하고 구현하며, 플러그인은 결과를 사실대로 정리하는 최소 규칙만 제공합니다.

## 네 단계

| 단계            | 모델이 하는 일                                                     | 남기는 것                              |
| --------------- | ------------------------------------------------------------------ | -------------------------------------- |
| 자료 확인       | 케이스에 맞는 기획서·Figma·레거시와 프로젝트 규칙을 읽음           | 구현 범위와 참고 기준                  |
| OpenSpec 문서화 | brief의 기획서 또는 feature 요청을 API 문서·Figma와 대조하고 보완  | 요구사항·수용 시나리오·미확정 항목     |
| 구현            | 프로젝트 구조와 디자인 시스템을 따라 코드 작성                     | 실제 Git 변경                          |
| 검증            | `test: on`이면 OpenSpec TDD, UI 화면 캡처·비교, `feature` E2E·영상 | 테스트 결과·일치율·Diff·영상           |
| Draft PR        | 현재 변경을 한국어로 요약                                          | 기능·API·화면·Gap·검증, `feature` 영상 |

## 중단 후 다시 시작하기

플러그인이 작업 상태를 저장하지 않습니다. 대신 코드 변경과 화면 증빙은 Git 작업 트리에 남습니다. 중단되면 같은 요청을 다시 실행해 현재 `git diff`에서 이어갑니다.

## 바로 멈추는 경우

아래 상황만 안전을 위해 즉시 멈춥니다.

- 대상 저장소 또는 쓰기 경로를 안전하게 확인할 수 없음
- 레거시 프로젝트를 수정하려는 상황
- 새 브랜치나 커밋을 만들 수 없음

`test: on`의 TDD 미확보, API 미확인, 화면 불일치는 멈춤 사유가 아닙니다. 구현 가능한 범위는 계속 진행하고 Gap에 남깁니다. `test: off`는 테스트를 생략했다는 사실을 PR 검증 항목에 남깁니다.
