title: Draft PR 형식
---

SpecToPR는 네 케이스에 같은 한국어 Draft PR 형식을 사용합니다. 복잡한 실행 메타데이터 대신 리뷰에 필요한 정보만 남깁니다. `feature`는 변경 기능 E2E와 사용자 흐름 영상 한 개를 추가합니다.

```md
# [Figma 구현] 결제 수단 선택 화면

> Draft PR · 화면 94.20% · Gap 1개

## 개발한 기능

- 저장된 카드와 새 카드 입력을 전환할 수 있습니다.

## 화면 일치율

| 화면 | 비교 기준 | 비교 횟수 | 일치율 | 결과 | 증빙 |
| 기본 상태 | Figma | 1/3 | 94.20% | 통과 | 기준 · 구현 · Diff |

## 사용한 API

| Method | Path | 사용 목적 |
| GET | /payment-methods | 결제 수단 조회 |

## Gap

| 확인 또는 개발이 필요한 내용 | 영향 | 다음 작업 |
| 카드 삭제 정책 | 낮음 | 정책 확인 후 버튼 추가 |

## 검증

- 관련 테스트 통과
```

`feature` PR에만 아래 섹션을 `사용한 API`와 `Gap` 사이에 추가합니다.

```md
## E2E 영상

- `spec-to-pr-evidence/shipping-address/change-shipping-address.webm`
  - 변경 기능만 고르는 E2E 통과
  - 주문 상세 → 배송지 선택 → 저장 → 변경 결과 확인
```

영상은 하나의 실제 사용자 흐름을 보여 줍니다. 화면 비교와 테스트를 대체하지 않으며, E2E를 실행하지 못하거나 영상을 남기지 못했다면 이유와 다음 작업을 Gap에 기록합니다.

## 작성 규칙

- 기능은 코드 파일 목록이 아니라 사용자가 할 수 있게 된 일을 한국어로 씁니다.
- API는 실제 추가·변경한 호출만 기록합니다. 없으면 `사용한 API 없음`을 씁니다.
- 화면 증빙은 기준·구현·Diff 파일 경로 또는 PR에서 볼 수 있는 링크를 넣습니다.
- 92% 미만으로 다시 비교했다면 `비교 횟수`와 각 차수의 Diff 경로를 적습니다. 최대 3회 뒤에도 미달하면 마지막 점수와 다음 작업을 Gap에 남깁니다.
- `feature`는 변경 기능 E2E 결과와 사용자 흐름 영상 한 개를 `E2E 영상` 섹션에 연결합니다.
- Gap이 없으면 `없음` 한 행을 남겨 누락과 구분합니다.
- 토큰, 쿠키, 비밀번호, 긴 내부 로그는 PR 본문에 쓰지 않습니다.
