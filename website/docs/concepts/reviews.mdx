## 순서는 권한 경계입니다

1. Orchestrator가 accepted contracts, 현재 diff, 실행 결과, evidence path와 `workflow_status` snapshot을 immutable packet으로 고정합니다.
2. 한 명의 implementation writer가 API-ready와 UI를 같은 `implementationContextId`로 제출합니다. API/UI parallel writer는 만들지 않습니다.
3. `functional-reviewer`는 수용 조건, API coverage, 테스트, architecture/security gate와 레거시 coverage를 read-only로 판정합니다.
4. UI scope의 `design-reviewer`는 baseline provenance, 실제 capture, visual report, interaction, responsive state, design-system, accessibility를 read-only로 판정합니다.
5. 두 verdict가 적용 가능한 gate를 통과해야 `report`와 draft `publish`가 열립니다.

:::info[리뷰어가 하지 않는 일]
Reviewer는 workflow MCP를 호출하거나 코드를 고치거나 점수를 새로 계산하지 않습니다. 특히 design reviewer는 `compare-visuals`가 만든 수치·diff·overlay와 provenance가 현재 packet에 묶였는지 검증합니다.
:::

## Scout는 reviewer도 writer도 아닙니다

XS/S에는 scout를 만들지 않습니다. M은 최대 1명, L/XL은 최대 2명의 read-only scout를 독립적인 탐색에만 쓸 수 있습니다. No nesting, browser 금지, workflow MCP 금지이며 구현을 병렬 작성하지 않습니다.
