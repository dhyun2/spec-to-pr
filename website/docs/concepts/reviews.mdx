## 역할과 검증 자료의 흐름

<AgentReviewMap locale="ko" />

## 순서는 권한 경계입니다

1. 진행 담당자가 승인된 계약, 현재 코드 차이, 실행 결과, 검증 자료 경로, `workflow_status` 상태 사본을 변경할 수 없는 하나의 검토 묶음으로 고정합니다.
2. 한 명의 구현 담당자가 API 준비 자료와 UI를 같은 `implementationContextId`로 제출합니다. API와 UI를 여러 담당자가 나눠 동시에 편집하지 않습니다.
3. `functional-reviewer`는 수용 조건, API 검증 현황, 테스트, 구조·보안 검사, 레거시 이관 현황을 읽기 전용으로 판정합니다.
4. UI 작업에서는 `design-reviewer`가 기준 화면의 출처, 실제 캡처, 화면 비교 보고서, 상호작용, 반응형 상태, 디자인 시스템, 접근성을 읽기 전용으로 판정합니다.
5. 두 판정이 적용 가능한 통과 조건을 모두 충족해야 보고서 작성과 초안 발행 단계로 이동합니다.

:::info[검토자가 하지 않는 일]
검토자는 워크플로 도구를 호출하거나 코드를 고치거나 점수를 새로 계산하지 않습니다. 특히 `design-reviewer`는 `compare-visuals`가 만든 수치·차이 이미지·겹침 이미지와 출처 정보가 현재 검토 묶음에 연결됐는지 확인합니다.
:::

## 조사 담당자는 구현하거나 판정하지 않습니다

작업량이 XS/S이면 별도 조사 담당자를 두지 않습니다. M이면 최대 1명, L/XL이면 최대 2명의 읽기 전용 조사 담당자를 서로 겹치지 않는 탐색에만 둘 수 있습니다. 조사 담당자는 다른 에이전트에게 다시 위임하거나 브라우저·워크플로 도구를 사용하지 않으며, 구현 파일도 편집하지 않습니다.
