title: 화면 비교
---

UI 작업은 케이스와 관계없이 화면 비교를 시도합니다. `skipped`, `waived`, 캡처 실패는 통과가 아닙니다.

## 동일한 캡처 조건

- 같은 route와 UI state
- 같은 fixture와 인증 상태
- 같은 viewport와 DPR
- 폰트·이미지·비동기 데이터가 모두 로드된 상태

이미지 크기가 다르면 점수를 만들지 않습니다. 기준 이미지를 바꾸거나 자르고, mask를 씌워 점수를 맞추는 일도 금지합니다.

## 92%와 핵심 UI 영역

전체 이미지의 일치율이 92% 이상이어야 합니다. 레거시 이관은 여기에 더해 검색·필터·목록·지도 조작처럼 빈 배경으로 가려질 수 있는 **핵심 UI 영역**도 각각 92% 이상이어야 통과입니다.

92% 미만이면 Diff를 보고 같은 조건에서 구현을 고친 뒤 다시 비교합니다. 유효 비교는 최초를 포함해 최대 3회입니다. 세 번째도 미달하거나 비교할 수 없으면 해당 상태는 Gap이며, Draft 전체도 `NOT VERIFIED`입니다.

## 레거시의 전체 범위

레거시는 한 장의 기본 화면을 비교하는 것이 아니라 source inventory의 router와 navigation에서 발견한 모든 사용자 노출 route와 대표 상태를 비교합니다. 각각 기준/이관/Diff가 있거나, 사유·영향·리뷰어 결정이 있는 제외여야 합니다. source inventory의 supporting import, asset, CSS selector, breakpoint, 지도 SDK 같은 runtime UI도 대상에 1:1로 보존됐다는 mapping이 있어야 합니다.

픽셀 외에 가벼운 라우트 동작 증빙도 확인합니다. 전체 E2E나 영상은 필요 없지만 실제 fixture 출처, 최종 URL, 구체적인 selector/text 기대값, API 필요 여부·인증 결과, console/network 진단 여부와 관련 오류, 대표 클릭·선택 전환 한 건을 기록합니다. 예상 밖 빈 화면·loading·오류, 임의 동적 파라미터, 비-2xx/CORS는 양쪽 이미지가 같아도 통과가 아닙니다. `criticalRegions` 전체를 viewport 하나로 지정하는 것도 핵심 UI 증빙이 아닙니다.

호스트에 Computer Use가 있으면 이미 로그인된 실제 앱을 조작해 기준·이관 결과를 캡처하는 것이 legacy의 기본입니다. Computer Use가 없거나 필요한 PNG를 만들 수 없으면 Browser/Playwright를 fallback으로 사용하고 provider·인증 상태·사유를 PR 좌우 이미지 비교 위에 한 번 공개합니다. 같은 조건의 PNG와 기능 검증을 확보했다면 도구 선택 자체는 Gap이 아닙니다. provider 기록이나 fallback 사유가 빠졌을 때만 Gap입니다.

## PR에서 이미지 보기

기준, 이관 결과, Diff 이미지를 `spec-to-pr-evidence/<change>/`에 stage·commit·push합니다. PR 본문에는 branch raw URL을 써서 경로·상태별 기준과 이관 이미지를 좌우 두 열에 표시하고 Diff는 링크로만 둡니다. 같은 이미지를 별도 화면 비교 표에 반복하지 않습니다. 로컬 절대 경로나 내부 로그 경로만 기록하면 리뷰어가 결과를 볼 수 없으므로 증빙으로 인정하지 않습니다.

화면 비교 실패가 구현 자체를 숨기지는 않습니다. Draft PR은 만들 수 있지만, 부족한 화면과 영향·다음 작업은 Gap 맨 위에서 확인할 수 있어야 합니다.
