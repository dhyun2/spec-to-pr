## 비교 기준부터 고정합니다

- `brief`, `feature`, `figma`: host-connected Figma가 가져온 node PNG가 baseline입니다.
- `legacy`: 별도 `legacyProjectRoot`를 실행해 같은 route/state의 화면을 캡처한 PNG가 baseline입니다.
- Actual은 대상 구현을 실행해 같은 route, state, viewport, device scale, deterministic fixture로 다시 캡처합니다.
- 두 capture는 provider, ISO `capturedAt`, project-relative PNG path, `sha256:` digest와 함께 현재 immutable packet에 고정됩니다.

## `compare-visuals`가 계산하는 값

Runtime은 `pngjs` 기반 bounded decoder로 두 PNG를 RGBA로 읽고, 너비와 높이가 다르면 즉시 거부합니다. Mask는 사유와 좌표가 있어야 하며 전체의 `20%`를 넘거나 모든 픽셀을 가리면 실패합니다.

각 비교 픽셀은 sRGB 채널을 선형 색 공간으로 바꾸고 alpha를 premultiply한 뒤 정규화된 RGBA Euclidean distance를 계산합니다. 바이트가 완전히 같은 픽셀은 exact match, 거리가 `0.02` 이하인 픽셀은 review match입니다. `reviewMatchRatio`가 최소 `98%`여야 통과합니다.

:::info[고칠 기회는 제한됩니다]
비교 총 3회, 즉 최초 1회 + repair 최대 2회입니다. Caller가 보낸 임의 score는 받지 않습니다. 캡처 단계가 같은 target 계약으로 baseline과 actual PNG를 만들고, production comparator가 두 PNG를 입력받아 `diff.png`, `overlay.png`, metrics를 반환합니다. 보고서는 캡처·비교 산출물의 경로와 digest를 한 packet에 묶습니다.
:::

## 누가 무엇을 믿을지 확인하나요?

`functional reviewer`는 시각 점수를 대체하지 않습니다. UI scope의 `design reviewer`가 baseline provenance, actual manifest, digest, threshold, mask 이유, diff/overlay 경로가 현재 packet과 일치하는지 확인하고 interaction·responsive·accessibility 증거를 함께 판정합니다.
