## 비교 기준부터 고정합니다

- `brief`, `feature`, `figma`: 연결된 Figma 기능으로 가져온 노드 PNG가 기준 화면입니다.
- `legacy`: 별도 `legacyProjectRoot`를 실행해 같은 경로와 상태에서 캡처한 PNG가 기준 화면입니다.
- 결과 화면은 대상 구현을 같은 경로·상태·화면 크기·기기 배율·고정된 테스트 데이터로 실행해 캡처합니다.
- 두 캡처는 자료 제공자, ISO 형식의 `capturedAt`, 프로젝트 상대 PNG 경로, `sha256:` 해시와 함께 현재 검토 묶음에 변경할 수 없도록 고정됩니다.

## `compare-visuals`가 계산하는 값

실행 엔진은 `pngjs` 기반의 제한된 디코더로 두 PNG를 RGBA 값으로 읽습니다. 너비나 높이가 다르면 비교를 시작하지 않습니다. 비교에서 제외할 영역은 사유와 좌표가 있어야 하며, 전체 화면의 `20%`를 넘거나 모든 픽셀을 가리면 실패합니다.

각 픽셀의 sRGB 채널을 선형 색 공간으로 바꾸고 알파 값을 미리 곱한 뒤, 정규화한 RGBA 유클리드 거리를 계산합니다. 바이트가 완전히 같은 픽셀은 정확히 일치한 것으로, 거리가 `0.02` 이하인 픽셀은 검토 기준에서 일치한 것으로 셉니다. `reviewMatchRatio`가 최소 `98%`여야 통과합니다.

:::info[고칠 기회는 제한됩니다]
화면 비교는 처음 한 번과 보정 후 최대 두 번을 합쳐 모두 세 번까지 할 수 있습니다. 호출자가 임의로 보낸 점수는 받지 않습니다. 캡처 단계가 같은 화면 계약으로 기준 PNG와 결과 PNG를 만들고, 실제 비교기가 두 파일을 읽어 `diff.png`, `overlay.png`, 측정값을 반환합니다. 보고서는 캡처와 비교 결과의 경로·해시를 하나의 검토 묶음에 연결합니다.
:::

## 누가 무엇을 믿을지 확인하나요?

`functional-reviewer`는 시각 점수를 대신 판정하지 않습니다. UI 작업의 `design-reviewer`가 기준 화면의 출처, 결과 화면 목록, 해시, 통과 기준, 제외 영역의 사유, 차이·겹침 이미지 경로가 현재 검토 묶음과 일치하는지 확인합니다. 상호작용·반응형·접근성 자료도 함께 판정합니다.
