UI 결과는 눈대중으로 통과 처리하지 않습니다. 비교 기준과 구현 화면을 같은 조건으로 캡처해 일치율을 계산합니다.

## 비교 기준

| 케이스    | 기준 이미지                        |
| --------- | ---------------------------------- |
| `figma`   | Figma 캡처                         |
| `legacy`  | 실행 중인 레거시 화면              |
| `brief`   | 제공된 Figma 또는 승인된 기획 화면 |
| `feature` | 제공된 Figma 또는 승인된 기획 화면 |

사내 디자인 시스템은 구현 재료입니다. 화면 일치율을 계산하는 기준 이미지는 아닙니다.

## 같은 조건으로 캡처하기

- 같은 경로와 UI 상태
- 같은 테스트 데이터
- 같은 화면 크기와 브라우저 환경
- 폰트와 이미지가 로드된 상태

이미지 크기가 다르면 일치율을 계산하지 않습니다. 억지로 잘라 맞추거나 임의의 점수를 넣지 않습니다.

## 92% 기준

비교 도구는 기준 이미지, 구현 이미지, 빨간 Diff 이미지를 만듭니다.

| 결과      | PR 작성 방식                                      |
| --------- | ------------------------------------------------- |
| 92% 이상  | 일치율과 증빙 경로를 기록                         |
| 92% 미만  | Diff를 보고 수정·재캡처·재비교, 최대 3회까지 시도 |
| 비교 불가 | 이유를 기록하고 Gap 추가                          |

## 92% 미만이면 세 번까지

최초 비교가 92% 미만이면 Diff를 보고 구현을 고친 뒤, **같은 기준 이미지·경로·상태·데이터·화면 크기**로 다시 캡처하고 비교합니다. 유효한 숫자 비교는 최초 비교를 포함해 최대 3회입니다.

1. 1차가 92% 이상이면 일치율과 증빙 경로를 기록합니다.
2. 1차 또는 2차가 92% 미만이면 Diff를 보고 수정한 뒤 다음 차수를 실행합니다.
3. 3차도 92% 미만이면 더 시도하지 않습니다. 마지막 점수와 1·2·3차 Diff를 PR에 남기고 Gap에 다음 작업을 적습니다.

캡처 실패나 이미지 크기 불일치는 유효 비교 횟수에 넣지 않습니다. 기준 이미지를 교체하거나 이미지를 자르고 mask를 씌워 점수를 맞추지 않습니다.

비교 결과와 상관없이 Draft PR은 만들 수 있습니다. 목표는 작업을 숨기지 않고 리뷰어가 차이를 보게 하는 것입니다.

## 3차도 미달한 PR 예시

```md
## 화면 일치율

| 화면 | 비교 기준 | 비교 횟수 | 일치율 | 결과 | 증빙 |
| 결제 수단 기본 상태 | Figma | 3/3 | 89.70% | Gap | 기준 · 1차 Diff · 2차 Diff · 3차 Diff |

## Gap

| 확인 또는 개발이 필요한 내용 | 영향 | 다음 작업 |
| 결제 수단 기본 상태가 Figma와 10.30% 차이 | 중간 | 간격과 버튼 높이를 보완한 뒤 다음 PR에서 재비교 |
```

## 단일 기능의 E2E 영상

`feature`는 변경 기능을 실제로 고르는 E2E를 한 번 실행하고, 그 사용자 흐름을 보여 주는 영상 한 개를 PR에 남깁니다. 영상은 버튼 클릭부터 결과 확인까지의 동작을 보여 주지만, 기준 이미지와의 화면 일치율 또는 테스트 결과를 대신하지 않습니다.
