## 비교 기준부터 고정합니다

- `brief`, `feature`, `figma`: 연결된 Figma 기능으로 가져온 노드 PNG가 기준 화면입니다.
- `legacy`: 별도 `legacyProjectRoot`를 실행해 같은 경로와 상태에서 캡처한 PNG가 기준 화면입니다.
- 결과 화면은 대상 구현을 같은 경로·상태·화면 크기·기기 배율·고정된 테스트 데이터로 실행해 캡처합니다.
- 두 캡처는 자료 제공자, ISO 형식의 `capturedAt`, 프로젝트 상대 PNG 경로, `sha256:` 해시와 함께 현재 검토 묶음에 변경할 수 없도록 고정됩니다.

실제 캡처는 후보별 `capture-session-v1`에서 수집합니다. 화면 비교, 기능 E2E, feature 영상, 성능 측정이 함께 필요해도 세션은 Playwright Test/CLI를 최대 한 번만 호출합니다. 이후 비교 단계는 세션의 실제 PNG와 구조화 결과를 검증해 영수증으로 연결할 뿐, 같은 화면을 다시 캡처하지 않습니다.

## `compare-visuals`가 계산하는 값

실행 엔진은 `pngjs` 기반의 제한된 디코더로 두 PNG를 RGBA 값으로 읽습니다. 너비나 높이가 다르면 비교를 시작하지 않습니다. 비교에서 제외할 영역은 사유와 좌표가 있어야 하며, 전체 화면의 `20%`를 넘거나 모든 픽셀을 가리면 실패합니다.

각 픽셀의 sRGB 채널을 선형 색 공간으로 바꾸고 알파 값을 미리 곱한 뒤, 정규화한 RGBA 유클리드 거리를 계산합니다. 바이트가 완전히 같은 픽셀은 정확히 일치한 것으로, 거리가 `0.02` 이하인 픽셀은 검토 기준에서 일치한 것으로 셉니다. `reviewMatchRatio`가 고정 기준 `92%` 이상이면 수치 게이트를 통과합니다. 정확히 92%도 통과하지만, 집중 UI 검증 실패를 상쇄하지는 않습니다.

:::info[고칠 기회는 제한됩니다]
화면 비교는 처음 한 번과 보정 후 최대 두 번을 합쳐 유효한 수치 비교 세 번을 사용자 확인 없이 자동으로 수행합니다. geometry·fixture·렌더러 계보가 맞지 않는 잘못된 취득은 시도 횟수를 소비하지 않습니다. 세 번째 유효 비교도 실패하면 실행은 `blocked`가 되고 디자인 검토로 넘어가지 않습니다. 발행 조건을 만족하면 실패한 최신 기준/결과를 같은 크기로 나란히 보여 주고 `diff.png`와 `overlay.png`를 따로 확인할 수 있는 진단 초안을 남깁니다. 호출자가 임의로 보낸 점수는 받지 않습니다.
:::

## 전체 점수만으로 잡을 수 없는 오류

- 호스트의 축소 썸네일은 목표 프레임으로 늘리지 않고 native export를 다시 얻습니다.
- 서로 다른 캡처 상태는 설명이 아니라 실제 state facts와 상태별 fixture 해시로 구분합니다.
- `Spot`, `Circle`, `Close` 같은 사내 아이콘은 정확한 공개 export와 `semantic/text/tertiary` 같은 semantic token에 매핑합니다.
- 기준 PNG는 증거일 뿐 제품 DOM·CSS·SVG·canvas의 레이어나 프록시가 될 수 없습니다.
- 이미지 크기, 표 위아래 border, 복사 버튼, 아이콘 geometry/color, 키보드 focus, heading, accessible name, action은 전체 점수와 별도의 집중 assertion으로 검증합니다.

## 누가 무엇을 믿을지 확인하나요?

`functional-reviewer`는 시각 점수를 대신 판정하지 않습니다. UI 작업의 `design-reviewer`가 기준 화면의 출처, 결과 화면 목록, 해시, 통과 기준, 제외 영역의 사유, 차이·겹침 이미지 경로가 현재 검토 묶음과 일치하는지 확인합니다. 상호작용·반응형·접근성 자료도 함께 판정합니다.
