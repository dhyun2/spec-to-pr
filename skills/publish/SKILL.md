# Publish

Call `workflow_status`. For normal delivery, require publish-ready status with no unresolved required gate and use `intent: ready`. A boundary stop such as `split-required` is not publish-ready and cannot waive review. For a currently blocked Run with requested draft publication, use `intent: blocked-diagnostic`; this preserves the blocker and may create or update a diagnostic draft without passing report or publish stages. A publish-precondition blocker remains local because the same precondition prevents a safe draft.

When status includes `workspaceBinding`, use its canonical repository root and repeat its exact `sourceBranch`, `targetBranch`, and `remoteName` for preview and execute. Never accept caller substitution of remote URL, provider, host, repository, or base ref. Verify the checked-out HEAD is the reviewed source commit, the bound target still resolves to `baseSha`, the bound remote still resolves to the stored sanitized `publicationTarget`, every intended change is committed, the working tree is clean, and source is at least one commit ahead of target. Self-hosted publication must have exact-host HTTPS web/API bases and a successful hostname-specific `gh`/`glab` auth probe; credentials are never persisted. Then call `workflow_publish` with the current `runId`, selected `intent`, `mode` set to `execute`, exact bound values, `pushBranch` set to `true` when needed, and `confirm` set to `true`. Runtime performs the same freshness check for preview and execute before any provider request.

Verify canonical `pr-report-v2.1` JSON and Markdown before publication. Ready and blocked-diagnostic reports use the same 15-section template, and every section declares `complete`, `not-run`, `blocked`, or `not-applicable`. Ready reports are current-packet bound; blocked reports omit stale packet or review claims but preserve the latest valid failed visual attempt and label it `blocked`. The sections expose public provenance, requirement/file traceability, API/legacy/visual/review/performance/feature evidence, blockers, risks, rollback, and exact unblock action without private absolute paths or URL secrets. For every visual target, render an equal-size baseline/current pair side by side and expose the `diff` and `overlay` as separately inspectable media. Treat partial media synchronization as a failed blocked publication: never omit a failed comparison image merely because the Run is blocked. Upload required visual/video assets only to the single managed GitHub branch `spec-to-pr/evidence`, under immutable run/packet/target/artifact paths. Validate the branch ref and use upload-commit-SHA-pinned URLs; never create per-Run evidence branches or mutate the source branch. Verify the returned draft URL, body synchronization, current-packet previews, diff/overlay links, and feature-video synchronization. Publishing never merges, approves, closes, or marks the request ready.

For GitLab, use project uploads first and render the validated exact-host absolute URL returned by GitLab, including project routes such as `https://<host>/-/project/<id>/uploads/<digest>/<file>`. If GitLab returns only `/uploads/<digest>/<file>`, reconstruct that project URL only from the numeric project ID resolved for the same target; reject any cross-host, traversal, credential, query, fragment, or malformed path. GitLab does not reliably inline WebM in MR Markdown: use a current embeddable browser screenshot as a clickable video thumbnail when available and retain a direct recording link. If an upload alone fails with 401, 403, 408, 429, 5xx, or a network failure, a ready legacy UI draft may use the `gitlab-raw-evidence` fallback only when every baseline/current screenshot is already a regular, tracked file on the reviewed source HEAD and its current SHA-256 matches the recorded artifact digest. Link those exact `<project>/-/raw/<head>/<path>` files in the side-by-side preview; do not fall back for synthetic diff/overlay images, missing head SHA, untracked/unsafe paths, digest mismatch, dirty worktrees, or feature video. Record the fallback mode and reason in the publish result. Any MR create/update failure remains a failed publication and is never masked by this fallback.

If blocked-diagnostic execution returns `reason: diagnostic-publication-uncertain`, stop: an expired or heartbeat-lost durable claim means the host mutation may have succeeded even though no result was recorded. `recoverUncertain` defaults to `false`; do not publish again automatically. Inspect GitHub/GitLab for an existing matching source/target draft, show the result to the user, and call the same `workflow_publish` action with `recoverUncertain: true` only after explicit user approval. This optional recovery adds no tool or stage, does not mark blocked report/publish stages passed, and is never auto-approved by the SDK.
